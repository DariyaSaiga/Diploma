# 📊 Сравнение моделей датасетов: mosei_cleaned vs mosei_bottleneck

## Исходные данные (одинаковые для обоих)

**Источник:** CMU-MOSEI (HDF5 файл)
- **Модальности:** Текст (слова) + Аудио (COVAREP) + Видео (OpenFace_2)
- **Метки:** 6 эмоций (happy, sad, anger, surprise, disgust, fear)
- **Split:** 70% train / 15% val / 15% test (stratified)

---

## 🔴 mosei_cleaned.pkl — "Классический подход"

### Что там сделано:

#### 1️⃣ **Аудио обработка:**
- ✅ Чтение COVAREP (74 признака)
- ✅ Очистка NaN/Inf → 0
- ✅ Clipping: значения в диапазон [-1000, 1000]
- **❗ Padding до фиксированной длины:**
  - Если аудио короче 50 фреймов → дополняем нулями
  - Если аудио длиннее 50 фреймов → обрезаем
  - **Результат:** ВСЕ сэмплы имеют форму `(50, 74)`
- ✅ StandardScaler нормализация (обучена на train)
- ✅ Сохранение scalers в `scaler_audio.pkl`

#### 2️⃣ **Видео обработка:**
- ✅ Чтение OpenFace_2 (713 признаков)
- ✅ Clipping: [-1000, 1000]
- **❗ Padding до 50 фреймов** (как аудио)
  - **Результат:** ВСЕ сэмплы имеют форму `(50, 713)`
- ✅ StandardScaler нормализация
- ✅ Дополнительный clipping после scaling: [-5.0, 5.0]
- ✅ Сохранение scalers в `scaler_visual.pkl`

#### 3️⃣ **Текст обработка:**
- ✅ Декодирование байтов → строки
- ✅ Удаление служебных токенов ("sp", "sil", "<unk>")
- ✅ Склеивание в одно предложение
- **❗ НЕ токенизируется BERT**
  - Сохраняется как сырой текст (строка)
  - BERT токенизация происходит в DataLoader (динамически)

### Структура каждого сэмпла:

```python
{
    "id":     "CMU_MOSEI_0001",           # идентификатор
    "audio":  np.ndarray(50, 74),         # ✅ ФИКСИРОВАННАЯ ДЛИНА
    "visual": np.ndarray(50, 713),        # ✅ ФИКСИРОВАННАЯ ДЛИНА
    "text":   "i am happy right now",     # строка (сырая)
    "label":  0                            # 0-5 (happy, sad, anger, ...)
}
```

### Размер датасета в памяти:

```
Примерно ~500 МБ (зависит от количества сэмплов)
- Меньше за счет фиксированного padding (50, 50)
- Можно загрузить весь в памяти
```

### ✅ Плюсы:
- 🟢 **Простой и быстрый** — фиксированные размеры
- 🟢 **Легко батчировать** — обычный `torch.stack()`
- 🟢 **Хорошо для простых моделей** (LSTM, CNN)
- 🟢 **Меньше памяти** — фиксированные размеры

### ❌ Минусы:
- 🔴 **Потеря информации** — если видео/аудио короче 50, добавляем шум (нули)
- 🔴 **Потеря информации** — если видео/аудио длиннее 50, просто обрезаем
- 🔴 **Неоптимально** — очень много паддинга для коротких видео
- 🔴 **Неэффективно** — нейросеть учится игнорировать нули

## 🟢 mosei_bottleneck.pkl — "Продвинутый подход"

### Что там сделано:

#### 1️⃣ **Аудио обработка:**
- ✅ Чтение COVAREP (74 признака)
- ✅ Очистка NaN/Inf → 0
- ✅ Clipping: [-1000, 1000]
- **✨ БЕЗ padding — сохраняется реальная длина**
  - Аудио остаётся как есть: `(Ta, 74)` где Ta - реальная длина
  - Ta варьируется от сэмпла к сэмплу!
- ✅ StandardScaler нормализация
- ✅ **Сохранение длины:** `audio_len = Ta` в каждом сэмпле

#### 2️⃣ **Видео обработка:**
- ✅ Чтение OpenFace_2 (713 признаков)
- ✅ Clipping: [-1000, 1000]
- **✨ БЕЗ padding — сохраняется реальная длина**
  - `(Tv, 713)` где Tv - реальная длина
  - Tv варьируется!
- ✅ StandardScaler нормализация
- ✅ Дополнительный clipping: [-5.0, 5.0]
- ✅ **Сохранение длины:** `visual_len = Tv`

#### 3️⃣ **Текст обработка:**
- ✅ Декодирование байтов → строки
- ✅ Удаление служебных токенов
- ✅ Склеивание в одно предложение
- **❗ Как и в cleaned: сохраняется сырой текст**

### Структура каждого сэмпла:

```python
{
    "id":         "CMU_MOSEI_0001",            # идентификатор
    "audio":      np.ndarray(Ta, 74),          # ✨ ВАРЬИРУЕТСЯ! (может быть 15-100)
    "audio_len":  15,                          # реальная длина аудио
    "visual":     np.ndarray(Tv, 713),         # ✨ ВАРЬИРУЕТСЯ! (может быть 20-95)
    "visual_len": 20,                          # реальная длина видео
    "text":       "i am happy right now",      # строка (сырая)
    "label":      0                             # 0-5
}
```

### Размер датасета в памяти:

```
Примерно ~300-400 МБ (меньше за счет переменного размера)
- Нет паддинга → экономия памяти
- Загружается весь в памяти
```

### Обработка в DataLoader:

```python
# bottleneck_dataset.py — make_collate_fn()
# Батчирование происходит так:

1. Динамический паддинг внутри батча
2. Все аудио в батче паддятся до max(audio_lens) в батче
3. Все видео в батче паддятся до max(visual_lens) в батче
4. Строятся bool-маски: True = реальный, False = padding

# Например, батч с 4 сэмплами:
# audio_lens = [15, 20, 18, 25]
# → Все паддятся до 25 в ЭТОМ батче

# В следующем батче может быть:
# audio_lens = [10, 12, 8, 14]
# → Все паддятся до 14 в ТОМ батче

Динамический паддинг! ✨
```

### ✅ Плюсы:
- 🟢 **НЕ теряется информация** — сохраняется реальная длина
- 🟢 **Экономия памяти** — нет фиксированного паддинга
- 🟢 **Маски для атентшена** — модель может игнорировать padding
- 🟢 **Оптимально для Transformer** — маски + relative positions
- 🟢 **Лучше работает** с переменными последовательностями

### ❌ Минусы:
- 🔴 **Сложнее в use** — нужна custom collate_fn
- 🔴 **Медленнее батчирование** — динамический паддинг
- 🔴 **Требует больше памяти при обучении** — мощный GPU
- 🔴 **Нужно обращать внимание на маски** — в модели

## 🎯 Для чего каждый подходит

### ✅ Используй **mosei_cleaned**, если:

1. **Простые модели:** LSTM, GRU, RNN, CNN
   - `[batch, 50, 74]` → просто в LSTM
   
2. **Быстрый прототип:** не хочешь думать о масках и динамическом паддинге
   
3. **Слабый GPU:** памяти мало, нужно экономить
   - Фиксированный размер → лучше оптимизируется
   
4. **Бейзлайн (baseline):** для сравнения с другими работами
   - Многие работы используют fixed padding
   
5. **Быстрая обработка:** не нужна оптимизация скорости

### ✅ Используй **mosei_bottleneck**, если:

1. **Transformer модели:** BERT, ViT, Attention-based
   - Маски позволяют эффективнее использовать attention
   
2. **Лучший результат (SOTA):** хочешь максимальную точность
   - Сохранение реальной длины = лучше модель учится
   
3. **Переменные последовательности:** видео не одинаковой длины
   - Динамический паддинг адаптируется к батчу
   
4. **Маски внимания:** Bottleneck Fusion, Multimodal Transformers
   - Требуется явная информация о реальной длине
   
5. **Исследование:** научная работа с акцентом на качество
   - Лучше сохраняет информацию

## ⚠️ Важные моменты

### Маски в bottleneck:
```python
# Маски в человеческом формате (True = реальный):
audio_mask[i, :real_len] = True   # реальные шаги
audio_mask[i, real_len:] = False  # padding

# Для MultiheadAttention нужно инвертировать:
key_padding_mask = ~audio_mask    # True = игнорировать
```

### Динамический паддинг:
```python
# Батч 1:
# audio_lens = [15, 20, 18, 25]
# → max = 25, все паддятся до 25

# Батч 2:
# audio_lens = [8, 10, 12, 9]
# → max = 12, все паддятся до 12

# НЕ всегда паддятся до 50!
```
